# IPv6 通用下载加速器

模仿 [UsbEAm 游戏下载助手](https://www.dogfight360.com/blog/19189/) 的思路做的**通用版**：不预设任何平台或 CDN 名单，给它任意域名/URL，它自己解析、实测、优选，然后通过本地代理把流量导到最快的 IP 上。

**核心区别：不改 hosts，不需要管理员权限。** 代理模式在 TCP 连接层把目标换成优选 IP，SNI/Host 保持不变，所以既能命中正确的 CDN 节点，又不动系统文件。

---

## 它到底做了什么

原工具（UsbEAm）的原理是四件事的组合，本工具把其中可通用的部分抽出来重做：

| 原工具做的事 | 本工具的实现 |
|---|---|
| 改 hosts 重定向到指定 IP | **不用 hosts**，本地 HTTP/HTTPS 代理在连接层换 IP |
| 监听 80/443 转发连接 | 监听 8899 做 HTTP 代理 + CONNECT 隧道，可选 SOCKS5 |
| 检测 IPv4/IPv6 是否可用 | 检测本机全局 v6 地址 + v6 出口真实 TCP 可达性 |
| CDN 优选（测速挑最快 IP） | 解析全部 A/AAAA → 逐个实测延迟 + **真实下载吞吐** → 排序 |
| 下载路径可视化、断连拉黑 | 实时统计（请求/隧道/流量/命中 IP）+ 一键拉黑某 IP |

### 三个关键设计

**1. 测速必须在首字节之后开始计时。**
如果把 TLS 握手算进分母，一个 403 报错页（19KB）也能算出很高的"速度"，优选结果就被带偏了。

**2. 传输窗口太短时读数不可信。**
千兆校园网镜像上 4MB 只要 40ms 就下完，此时数据主要来自内核 socket 缓冲，读数虚高。所以做了**基于时间预算的两段式自适应**：小样本先跑，窗口不足就自动加大重测，同时有 64MB 硬上限，避免慢链路上为了测速下掉几十 MB。

**3. 只给域名时要去"标定"一个可下载的大文件。**
直接测 `https://域名/` 是错的——根路径往往只有几十 KB 的目录列表页。程序会按常见镜像路径（`/ubuntu/ls-lR.gz` 等）逐个试探，找到真正的大文件再测。**标定不出来就不给吞吐数据，退回按延迟排序**，绝不编造数字。

### 两阶段路由（首包延迟的关键）

- **阶段一**：只做 TCP 延迟探测，几十毫秒出结果，立刻放行请求 → 冷启动 TTFB 约 30ms
- **阶段二**：后台跑真实吞吐测速，完成后就地更新排序 → 后续请求享受吞吐优选

早期版本在阶段一就做完整测速，导致首次访问首字节要等将近 1 秒。同时把"探测 443/80/8080/8443 四个端口"改成**只探实际要连的那个端口**，这一项就省掉了约 850ms。

## 快速开始

### 方式一：双击启动（推荐）

```
双击 start.cmd
```

然后浏览器打开 `http://127.0.0.1:8900`。

### 方式二：一键设置系统代理

```
双击 一键开启系统代理.cmd
```

会自动把系统代理指向 `127.0.0.1:8899`，关掉窗口时**自动还原**原来的设置（含绕过列表）。

> ⚠️ 如果这个窗口被**强行结束**（任务管理器结束进程、系统崩溃、直接断电），
> 还原逻辑来不及执行，代理会停留在 `127.0.0.1:8899` 而那里已经没有服务，
> 表现就是"突然上不了网"。这时双击 **`restore-proxy.cmd`** 即可恢复——
> 原始设置（含你的绕过列表）在改代理之前就写进了 `proxy-backup.json`。
>
> 实在不行也可以手动恢复：设置 → 网络和 Internet → 代理 → 关掉"使用代理服务器"。

### 方式三：命令行

```bash
node server.js                      # 启动代理 + 界面
node server.js --port 9000          # 换端口
node server.js --policy v6          # 强制只走 IPv6
node server.js --socks5 1088        # 额外开 SOCKS5
node server.js --local 2001:da8:e000:9::c90c   # 绑定指定出口地址
node server.js --host 0.0.0.0       # 给局域网设备（Switch/PS/Xbox）用
```

需要 Node.js 16+（[下载](https://nodejs.org/)）。**没有任何第三方依赖**，不需要 `npm install`。

### 启动脚本出问题了？

用 `start-ascii.cmd`（内容和 `start.cmd` 完全相同，纯 ASCII，任何环境都能用）。

需要重新生成这些 `.cmd` 的话：`node make-launchers.js`。

`start.cmd` 如果检测到加速器已经在运行，不会报错，而是直接帮你打开界面。

## 怎么配到各种程序里

| 程序 | 设置 |
|---|---|
| 浏览器 | 系统代理（用一键脚本），或手动设 HTTP/HTTPS 代理 `127.0.0.1:8899` |
| IDM | 选项 → 代理 → 使用系统代理 / 手动填 `127.0.0.1:8899` |
| aria2 | `--all-proxy=http://127.0.0.1:8899` |
| curl | `curl -x http://127.0.0.1:8899 ...` |
| Steam / 游戏客户端 | 若支持 HTTP 代理则填 `127.0.0.1:8899`；不支持就用下面的 hosts 模式 |
| Switch / PS / Xbox | `--host 0.0.0.0` 启动，主机代理填本机局域网 IP + 端口 |

**不需要配代理的备用方案**：界面上有「hosts 增强模式」，给那些无视系统代理的程序用。只写入一段带标记的区块，一键完全还原（需要管理员权限运行）。

---

## hosts 增强模式

只操作 `# ==== IPv6 Accelerator BEGIN/END ====` 之间的内容，绝不碰你原有的 hosts 内容；每次写入前会在 `backup/` 目录留一份带时间戳的备份。

- 界面「优选并写入」：对填入的域名测速后把最优 IP 写进 hosts，并自动 `ipconfig /flushdns`
- 界面「还原 hosts」：删掉受管区块，其他内容原样保留

失败时会明确告诉你是"权限不足"，而不是静默失败。

## 重要：IPv6 加速的前提

**v6 路径必须真的比 v4 快，这个工具才有意义。**

它不会凭空造出 IPv6，也不会让被墙的连接变得可用——它只做一件事：**在可用的地址里挑实测最快的那个，并且让你能验证到底哪个快。**

很多国内 CDN 的 v6 路径确实更空（教育网/CERNET 尤其明显），但也有大量反例。上面浙大镜像的例子就是 v4 更快。所以：

> **先跑 `node cli.js <你的目标>` 看对比数据，再决定要不要用这个工具。**

如果本机没有全局 IPv6 地址，程序会明确提示，功能退化为"IPv4 多 IP 优选"（仍然有用：能从多个 A 记录里挑最快的，也能自动跳过走不通的节点）。

### 为什么 .cmd 里一个中文都没有

`cmd.exe` 是按**控制台代码页逐字节**读取批处理文件的。中文批处理只要编码和代码页对不上
（UTF-8 带 BOM、UTF-8 无 BOM、GBK 不匹配……），就会出现：行首字符被吃掉、`echo` 变成 `ho`、
注释行被当命令执行、中文变乱码。而且不同 Windows 环境下表现还不一样。

这个坑本项目真实踩到了：第一版 `start.cmd` 存成 UTF-8 带 BOM，双击后满屏报错完全无法运行。

最终方案：**`.cmd` 内容全部 ASCII，所有中文提示交给 Node 输出**。
Node 通过 `WriteConsoleW` 写控制台，和代码页无关，中文永远正确。
文件名仍可以是中文（NTFS 文件名是 UTF-16，不受控制台编码影响）。

### 自测

node test-probe.js     # 解析/延迟/吞吐/竞速/路由表
node test-e2e.js       # 界面/API/策略切换/真实经代理下载

## 代理性能实测

本机（浙大校园网，千兆 IPv6）实测：

| 路径 | 吞吐 | TTFB |
|---|---|---|
| 直连 | 102.6 MB/s | 3 ms |
| 经本代理 | 98.7 MB/s | 4 ms |

代理本身开销约 4%。同一份 8MB 下载经代理耗时 96ms，冷启动首字节 33ms。

## 出问题了怎么办

**第一步：看 `startup.log`。** 双击脚本时无论成功失败都会写这个文件，
里面记录了完整过程（Node 路径、端口探测结果、服务退出码、异常堆栈）。
看不懂就直接把这个文件的内容发出来。

| 现象 | 原因 | 解决 |
|---|---|---|
| **黑窗口一闪而过** | 加速器已经在运行，脚本识别后正常退出（这是**正常行为**，不是崩溃） | 直接用界面 <http://127.0.0.1:8900>；窗口现在也会停下等按键，能看到提示 |
| 窗口提示"端口已被其他程序占用" | 8899/8900 被别的程序占了 | 换端口：`start.cmd --port 8999` |
| 双击满屏报错 | 批处理编码问题 | 改用 `start-ascii.cmd`，或跑 `node make-launchers.js` 重新生成 |
| **突然上不了网** | 用了 `一键开启系统代理.cmd` 但窗口被强杀，代理卡在已停止的端口 | 双击 `restore-proxy.cmd`；或手动：设置 → 网络和 Internet → 代理 → 关掉"使用代理服务器" |
| 界面能开但下载没变快 | 该目标 IPv6 本来就不快 | 跑 `node cli.js <目标>` 看实测对比，v4 快就用 `--policy v4` 或干脆别用 |
| 提示"本机 IPv6 不可用" | 没有全局 v6 地址或 v6 出不去 | 功能退化为 IPv4 多 IP 优选，仍可用；要真正的 v6 需运营商/路由器支持 |
| 测速显示"样本不足/仅延迟" | 目标没有足够大的文件可供测吞吐 | 正常。程序不会编造数字，改用延迟排序；也可直接给一个具体的大文件 URL |

### 关于"闪退"

如果加速器**已经在运行**，再双击一次 `start.cmd`，它会：

1. 通过 `accelerator.pid`（以及界面端口的服务标识）确认已有实例
2. 打印"加速器已经在运行中"，并帮你打开界面
3. 退出码 0，窗口停下等你按键

早期版本这一步有个真实 bug：它去探测**代理端口**冒充 HTTP 服务，而代理会按转发规则
解析请求，探测永远失败 —— 于是它误以为没有实例在运行，启动第二个，撞端口后以 code=1 退出，
表现就是"黑窗口闪退"。现在改用 PID 文件 + 带服务标识的健康检查来判断。

## 已知限制

- 代理模式只影响**遵守系统代理设置**的程序；不遵守的用 hosts 模式兜底
- 游戏主机（Switch/PS/Xbox）需要 `--host 0.0.0.0` 且主机与电脑同网段
- 部分 CDN 对单 IP 限制连接数，最高速率可能受限（这与原工具遇到的是同一类问题）
- 吞吐测速会消耗一定流量：默认每候选 4MB，快链路上最多放大到 64MB，可用 `--bytes` 限制
- 探测阶段对证书异常是宽容的（只关心速度），代理转发阶段默认**同样不校验证书**以保证兼容性；如需严格校验可改 `lib/proxy.js` 里的 `rejectUnauthorized`
