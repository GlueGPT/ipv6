# IPv6 通用下载加速器

给任意域名或下载链接实测出最快的 IP，然后通过**本地代理**或 **hosts 重定向**把流量导过去。

参考 [UsbEAm 游戏下载助手](https://www.dogfight360.com/blog/19189/) 做的通用版：它预设了各游戏平台的域名和 CDN 规则，本工具不预设——给它任何目标，它自己解析、自己测、自己挑。

**普通使用不需要管理员权限。** 只有游戏平台模式需要（因为要改 hosts）。

---

## ⚠️ 先读这一段：IPv6 不一定更快

这是本工具最重要的一个认知，也是它存在的理由之一。

**它不会凭空造出 IPv6，也不会让被墙的连接变得可用。** 它只做一件事：在可用的地址里挑出实测最快的那个，并且**让你能验证到底哪个快**。

很多国内 CDN 的 v6 路径确实更空（教育网 / CERNET 尤其明显），但反例同样多。本机实测：

| 目标 | IPv6 | IPv4 | 结论 |
|---|---|---|---|
| 某高校镜像（校园网内） | 54 MB/s | 76 MB/s | **v4 反而快 1.4 倍** |
| 另一高校镜像 | 15.5 MB/s | 15.0 MB/s | 基本持平 |

所以正确用法是**先测再用**：

```bash
node cli.js mirrors.ustc.edu.cn
```

```
目标  https://mirrors.ustc.edu.cn/
域名 mirrors.ustc.edu.cn   端口 443   解析到 IPv6 3 个 / IPv4 3 个

  #   IP 地址                                    协议   延迟      吞吐         状态
  ────────────────────────────────────────────────────────────────────────────────
  1   202.141.160.110                            IPv4   25 ms    29.3 MB/s    可用
  2   202.38.95.110                              IPv4   15 ms     5.9 MB/s    可用
  3   2001:da8:d800:95::110                      IPv6   15 ms     2.0 MB/s    可用

  ▶ IPv4 反而快 4.97 倍，这个目标不该走 IPv6
```

## 快速开始

### 1. 装 Node.js

只有这一个前置条件（[nodejs.org](https://nodejs.org/) 下载 LTS，一路下一步）。

**没有任何第三方依赖**，不需要 `npm install`。

### 2. 双击 `start.cmd`

会出现一个菜单：

```
  IPv6 通用下载加速器

  当前状态：管理员 否   hosts 可写 否   系统代理 未开启

  提示：游戏平台（Steam / Epic 等）需要管理员权限；
        浏览器和 IDM 的代理模式不需要，选 1 或 2 即可。

  [1] 普通启动
      只开界面。浏览器 / IDM 手动填代理 127.0.0.1:8899
  [2] 加速启动 （推荐）
      自动把系统代理指向本程序，浏览器 / IDM 立刻生效
      退出时自动还原原来的代理设置
  [3] 加速启动 + 管理员权限
      上面的功能，外加游戏平台模式（Steam / Epic / 战网……）
  [4] 管理员启动，不动系统代理
      只想用游戏平台模式、不想改系统代理时选这个
  [h] 查看命令行用法
  [q] 退出

  请选择 [1/2/3/4/h/q]（直接回车 = 2 加速启动）：
```

**直接回车就行**（等于选 2）。选 3 会弹一次 UAC 授权，之后游戏平台也能用。

启动后浏览器会自动打开 <http://127.0.0.1:8900>。

### 3. 就这样

选 2 的话，浏览器和 IDM 已经开始走加速了。关掉那个黑窗口 = 停止加速并还原代理设置。

## 两种加速机制

界面上方的「选择平台」把程序按机制分成两类。这不是设计选择，是因为**游戏平台的下载器根本不读系统代理**：

| 机制 | 适用程序 | 原理 | 管理员 |
|---|---|---|---|
| **本地代理** | 浏览器 / IDM / aria2 / curl | 程序在连接层把目标换成优选 IP，SNI 与 Host 不变 | 不需要 |
| **hosts 重定向** | Steam / Epic / 战网 / EA / 育碧 / Riot / R星 / GOG / Amazon / WG / Xbox | 把内容 CDN 域名指向优选 IP | **需要** |

共内置 14 个平台。点卡片 → 展开详情 → 一键开启。

**多模式共存**：hosts 条目带模式标记，开 Epic 不会冲掉已配好的 Steam；「关闭并还原」只移除该平台的条目；你原有的 hosts 内容一个字都不会动。

## 命令行用法

```bash
# 启动（等价于菜单里的选项）
start.cmd --proxy             # 加速启动 + 自动设系统代理
start.cmd --elevate           # 管理员启动（游戏平台模式）
start.cmd --elevate --proxy   # 管理员 + 系统代理
start.cmd --port 9000         # 换端口（界面端口自动 9001）
start.cmd --no-open           # 启动但不自动开浏览器

# 命令行测速（不用开界面）
node cli.js --env                          # 只看本机 IPv6 环境
node cli.js mirrors.ustc.edu.cn            # 对比该目标的 v4 / v6 实测速度
node cli.js <URL> --quick                  # 只测延迟，不下载
node cli.js <URL> --json                   # 输出 JSON
node cli.js <URL> --bytes 16               # 每轮最多下 16MB 用于测速

# 高级选项
node server.js --policy v6                 # 强制只走 IPv6
node server.js --socks5 1088               # 额外开 SOCKS5
node server.js --local 2001:da8:e000:9::c90c   # 绑定指定出口地址
node server.js --host 0.0.0.0              # 给局域网设备（Switch/PS/Xbox）用
```

| 程序 | 怎么配 |
|---|---|
| 浏览器 | 用菜单选项 2（自动设系统代理），或手动填 HTTP/HTTPS 代理 `127.0.0.1:8899` |

## 出问题了怎么办

### 第一步永远是看 `startup.log`

每次启动都会写这个文件，里面有完整过程：Node 路径、端口探测结果、实例替换、服务退出码、异常堆栈。**看不懂就直接把内容发出来。**

### 关闭程序时会自动还原吗

**会，而且是双保险。** 分三种情况：

| 你怎么关的 | 结果 |
|---|---|
| 在黑窗口里按 `Ctrl+C`，或正常关掉那个窗口 | 程序自己还原，实测 0.5 秒内完成 |
| **任务管理器结束进程 / 程序崩溃 / 强行关窗口** | **看门狗兜底还原**，实测 0.5 秒内完成 |
| 只关掉浏览器标签页 | 什么都不变——加速还在生效，因为程序还在跑 |

还原是完整的：`ProxyEnable`、`ProxyServer`、以及**你原有的 `ProxyOverride` 绕过列表**都会恢复原样。

#### 为什么要额外做一个看门狗

因为 Windows 上"退出时还原"根本不可靠。实测确认：

- 任务管理器结束进程 → 收尾代码不执行
- 外部 `process.kill` 发 `SIGINT`/`SIGTERM` → 直接 `TerminateProcess`，
  **Node 的 signal handler 和 `exit` 事件都不会触发**
- 关闭控制台窗口 → 同上，而且系统只给几秒
- 蓝屏 / 断电 / 重启 → 无从执行

所以改成了：启动时派一个**独立的小进程**（`watchdog.js`）盯着主进程，主进程一旦消失就由它来还原。
用令牌区分会话，主进程正常收尾时会删掉恢复文件，看门狗看到文件没了就安静退出，不会打架。

这个看门狗是被同一类问题逼出来的——我自己在测试期间就留下过"代理开着但服务没了"的残局，
表现就是直接上不了网且完全不知道为什么。

#### 万一还是断网了

双击 **`restore-proxy.cmd`**。它会读取 `proxy-backup.json` 里记录的原始设置并恢复。

实在不行手动改：**设置 → 网络和 Internet → 代理 → 关掉「使用代理服务器」**。

### 常见情况

| 现象 | 原因 | 解决 |
|---|---|---|
| **突然上不了网** | 代理卡在已停止的端口（现在看门狗会自动处理，极端情况仍需手动） | 双击 `restore-proxy.cmd` |
| 界面提示"需要管理员" | 当前不是管理员权限 | 重新双击 `start.cmd`，选 **3** 或 **4**（会自动顶掉旧实例） |
| 双击后窗口一闪而过 | 加速器已经在运行，脚本识别后正常退出 | 直接开 <http://127.0.0.1:8900>；窗口现在会停下等按键，能看到提示 |
| 提示"端口已被其他程序占用" | 8899/8900 被别的程序占了 | `start.cmd --port 8999` |
| 界面能开但按钮没反应 | 页面脚本报错 | 按 `F12` 看控制台红色报错，发出来 |
| 测速显示"样本不足 / 仅延迟" | 目标没有足够大的文件可供测吞吐 | 正常。程序不会编造数字，改用延迟排序 |

### 手动还原

- 系统代理卡住 → 双击 `restore-proxy.cmd`
- hosts 条目要清 → 界面上「还原所有 hosts 条目」，或手动删掉 `# ==== IPv6 Accelerator BEGIN/END ====` 之间的内容
- 想看历史备份 → `backup/` 目录（保留最近 20 份）

## 设计与踩坑记录

这部分记录了几个"看起来对但实际是错的"实现，也是本项目的价值所在。

### 测速：三个必须处理的坑

**坑 1：速度只能在首字节到达之后计时。** 如果把 TLS 握手算进分母，一个 19KB 的 403 报错页能算出很高的"速度"，优选结果直接被带偏。

**坑 2：传输窗口太短，测到的是内核缓冲速度。** 千兆校园网镜像上 4MB 只要 40ms 就下完，此时数据主要来自 socket 缓冲区。所以做了基于时间预算的两段式自适应采样。

**坑 3：Node 的 `setTimeout` 是 socket 空闲超时，不是总时长超时。** 慢链路上一直接收到数据、只是很慢，它**永远不会触发**。实测本该 4 秒截止的候选，每个跑了 17.5 秒。改成用绝对墙钟截止。

**坑 4：只给域名时不能直接测根路径。** `https://域名/` 往往只有几十 KB 的目录列表页。程序会先按常见镜像路径"标定"出一个可下载的大文件；标定不出来就**不给吞吐数据、退回按延迟排序**，绝不编造数字。

### 两阶段路由

首包只做 TCP 延迟探测（几十毫秒出结果就放行），真实吞吐测速放后台做、完成后就地更新排序。早期版本在首包路径上做完整测速，首次访问首字节要等将近 1 秒。

另外早期版本会在每个 IP 上**串行试 443→80→8080→8443 四个端口**，每个失败都要等满超时。代理本来就知道要连哪个端口，改成只探那一个端口后，冷启动从 928ms 降到 33ms。

### PowerShell 提权：别把脚本塞进 -Command

多层引号转义会让 `$ErrorActionPreference = "Stop"` 的引号被吃掉、静默退化成 `= Stop`——命令表面还能跑，错误处理已经失效。现在改成写临时 `.ps1` 用 `-File` 执行。

另外 PowerShell 5.1 的 `-ArgumentList` 把数组元素用空格拼接**且不加引号**，路径带空格（比如用户名带空格）就会被拆开。所以要自己加引号。

### 批处理文件里一个中文都不能有

`cmd.exe` 按控制台代码页**逐字节**读批处理文件。中文 `.cmd` 只要编码和代码页对不上，就会出现行首字符被吃掉、`echo` 变成 `ho`、注释行被当命令执行。这个坑真实踩到过：第一版 `start.cmd` 存成 UTF-8 带 BOM，双击后满屏报错完全无法运行。

现在 `.cmd` 内容**全部 ASCII**，只负责找 Node.js；所有中文提示交给 Node 输出（走 `WriteConsoleW`，和代码页无关）。

### 入口越少越不容易出错

曾经有 5 个 `.cmd` 各自都能启动，结果用户连续踩坑：先用 `start.cmd` 起了一个普通权限实例，再用管理员脚本时被"已有实例"劝退——**管理员权限根本没生效**，界面却仍然提示需要管理员。

现在只有 2 个 `.cmd`，并且 `--elevate` 会主动顶掉旧实例（先 SIGTERM 让它走完还原流程，再确认端口释放）。

## 已知限制

- **吞吐读数是偏低的下界，不是精确带宽。** 自适应采样要在"准"和"快"之间取舍，实测在部分镜像上低到真实值的 1/7（`node bench.js` 有对照实验）。**排序结论可靠**（谁更快不会错），但别拿它当带宽测试工具。
- 只对**延迟最优的前 6 个候选**测吞吐（每协议族最多 3 个），其余按延迟排名。这是为了控制耗时——三十个候选逐个测能把一次优选拖到几十秒。
- 代理模式只影响**遵守系统代理设置**的程序；游戏平台必须用 hosts 模式。
- 游戏主机（Switch / PS / Xbox）需要 `--host 0.0.0.0` 且主机与电脑同网段。Xbox 主机默认 IPv6 优先且无法自定义，可能需要关掉路由器的 IPv6。
- 部分 CDN 对单 IP 限制连接数（战网客户端只发 3 个连接），最高速率可能受限。
- 代理转发阶段默认**不校验证书**以保证兼容自签证书的更新器；如需严格校验，改 `lib/proxy.js` 里的 `rejectUnauthorized`。

## 测试

```bash
node test-ui.js        # 界面与构建脚本：语法、重复声明、死引用、真跑一遍页面脚本、菜单烟雾测试
node test-hosts.js     # hosts 多模式：共存、按模式还原、用户内容零破坏
node test-restore.js   # 系统代理还原：正常退出 / 被强杀 / 关页面 三种情况
node test-replace.js   # 实例替换：真的起一个实例再顶掉它
node test-elevate.js   # 提权脚本的参数拼装（不弹 UAC）
node test-probe.js     # 探测：解析 / 延迟 / 吞吐 / 竞速 / 路由表
node test-e2e.js       # 端到端：API、真实经代理下载、策略切换
```

换网络后如果 `test-e2e.js` 卡住，用环境变量指定测试目标：

```bash
ACCEL_TEST_TARGET=https://mirrors.aliyun.com/ubuntu/ls-lR.gz node test-e2e.js
```

**为什么界面要单独做静态检查**：因为踩过一次真实事故——重构时在页面脚本里留下了重复的 `let MODES` 声明，语法错误导致**整个 `<script>` 块一行都不执行**：平台卡片不渲染、状态永远停在"检测中…"、按钮没反应。而我当时的验证方式是"抓 HTML 看标签在不在"，**完全测不出 JavaScript 的问题**，所有检查都通过、界面却是死的。

现在 `test-ui.js` 会扫描**全部 .js 文件 + 页面内联脚本**的语法和顶层重复声明，并用 `vm` + 最小 DOM 桩**把页面脚本真跑一遍**、喂假 API 响应、确认平台宫格真的渲染出卡片。同一类事故后来又在 `make-launchers.js` 里复发过一次，正是这个检查先抓到的。
