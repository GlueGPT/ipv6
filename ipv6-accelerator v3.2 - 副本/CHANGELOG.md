## [3.2.0] — 2026-10-05

界面重做 + 新增功能的一版。**启动方式、命令行参数、hosts 与代理机制全部不变**，
老用法（`start.cmd`、菜单选项、`--port` / `--policy` / `--socks5`）一字未改。

### 新增

**界面里的一键系统代理开关**（`lib/sysproxy.js` · `server.js`）

以前只能在启动菜单里选「加速启动」，程序运行起来之后想开关就得退出重来。
现在概览页有一个开关，随时打开 / 关闭，关闭即还原成你原来的设置。

它沿用启动器那套安全规矩，不是另写一套：

- 读取三态化，`reg query` 失败时**拒绝接管**，绝不据此删除用户的配置；
- 备份用 `'wx'` 独占创建，绝不覆盖上一次会话留下的备份；
- 用户原有的绕过列表会被保留并追加默认值，不会替换掉；
- 开启的同时派出看门狗（`watchdog.js --file proxy-backup-ui.json`），
  进程被强杀时代理照样能还原；
- 备份文件与启动器的 `proxy-backup.json` **分开存放**，两边互不覆盖。

界面开启的代理也在退出路径上还原，并且 `restore-proxy.cmd` 现在两份备份都会处理
（否则残留的备份会让界面拒绝再次接管）。

**界面整体重做**（`public/index.html`）

- 侧边导航分六个视图：概览 / 测速 / 平台 / hosts / 路由与连接 / 设置与帮助。
  首屏不再是"所有东西堆在一页上"。
- 深色 / 浅色主题切换，选择记在本地，下次打开还是那个。
- 概览页有实时速率曲线（下行 / 上行双线，最近 90 秒）和四块统计磁贴。
- 平台页可以按名字搜索、按「本地代理 / hosts 重定向 / 已加速」筛选，
  并且能依次开启全部可用平台。
- 测速结果表头可点排序；最近测过的目标会留成快捷标签；结果能导出 CSV。
- 新增「端到端验证」：同一个地址分别测直连和走代理，直接给出比值 ——
  用来确认加速到底有没有生效，而不是只看候选 IP 的理论速度。
- hosts 页列出当前受管条目，可以逐条删除。
- 路由表可以给单条域名「忘记」，也能整体清空；旁边新增最近连接记录。
- 新增 DNS 查询小工具（看一个域名解析出了哪些 A / AAAA）。
- 右下角 Toast 通知，操作有反馈；页面切到后台自动暂停轮询。

**hosts 模式改为「按需提权」，不必再把整个程序重启成管理员**（`admin-hosts.js` 新文件 · `server.js`）

这是"管理员模式根本用不了"的根治办法。原来的唯一路径是：
关掉程序 → 右键 `start.cmd` → 以管理员身份运行 → 再选 3。
这条链路又长又容易走岔，而且用户往往已经在用浏览器代理，
为了给 Steam 加速要把整套程序重启一遍。

实际上**只有写 hosts 这一个动作需要管理员**：代理、测速、优选全都不需要。
现在改成：程序照常用普通权限跑，点「一键开启加速」时才弹一次 UAC，
由一个短命的管理员子进程写完 hosts 就退出。主进程权限始终不变。

父子进程靠临时 JSON 文件通信（`Start-Process -Verb RunAs` 只能"启动"，
拿不到子进程退出码和 stdout）。用户点 UAC 可能要一会儿，等待给到 180 秒。

**选了管理员启动，但管理员权限根本没生效**（`launcher.js`）

`--elevate` 没有转发给提权后的新进程。于是新进程一检测到
"已经有实例在跑"（那个旧的、非管理员的实例确实还在），
就走"打开浏览器 → 退出"分支，旧实例继续运行。
表现是：UAC 点了「是」、新窗口也弹了，界面却仍然显示"需要管理员"。

菜单里还有第二条同样的坑：已是管理员时选 3/4 会**降级**成不带 `--elevate`，
结果一样不会替换旧实例。现在 3/4 一律带 `--elevate` ——
"当前窗口是不是管理员"和"正在跑的实例是不是管理员"是两件事。

**选完管理员启动后没有自动弹出网页**（`launcher.js`）

两个原因，都已修：

1. 浏览器是**提权后的进程**去开的。`start http://...` 会以高完整性级别
   拉起浏览器，Edge / Chrome 在这种情况下经常直接打不开。
2. 没有等新实例就绪就打开，用户拿到的是"无法访问此页面"。

现在：转发 `--no-open`，由**未提权**的旧进程等新实例就绪（并排除旧实例的 pid）
后再打开浏览器；提权进程自身如果确实要开，则走 `explorer.exe`
（它以普通权限在跑，浏览器就不会被以管理员身份拉起来）。

**把 127.0.0.1 当成最优 IP 写进了 hosts**（`lib/probe.js` · `server.js`）

实测在 hosts 里见过这样一条：

```
127.0.0.1  steamcdn-a.akamaihd.net   v4 0.5ms
```

成因是 DNS 被劫持或短暂抽风，把一个公网 CDN 域名解析到了回环地址。
回环地址在本机**一定连得上**（0.5ms，全部端口握手成功），
于是测速排名里它永远第一，然后被写进 hosts ——
后果不是"没加速"，而是**那个 CDN 域名彻底废掉**，Steam 下载直接卡住。

现在 `probe.isRoutableIp()` 会挡掉回环 / 未指定 / 链路本地地址：
它们不会进入 v4/v6 汇总，不会被写进 hosts，界面上还会明确标成「本机地址」。
私有网段（10.x / 192.168.x）不算不可达 —— 内网镜像是合法场景。

**界面与提示里引用了并不存在的 .cmd**（`server.js` / `lib/presets.js` / `launcher.js`）

提示里让用户去双击「以管理员身份运行.cmd」「一键开启系统代理.cmd」，
而项目里根本没有这两个文件（只有 `start.cmd` 和 `restore-proxy.cmd`）。
已全部改成实际存在的入口。

**「关掉程序之后网页全部打不开」现在能自己发现并一键修好**（`lib/sysproxy.js` · `restore-proxy.js` · 界面）

成因是一种此前**没有任何机制会处理**的状态，这里叫它"孤儿代理"：

- 系统代理开关开着，指向 `127.0.0.1:<本程序端口>`；
- 那个端口上已经没有服务（程序关了）；
- 而且**没有任何备份文件**。

看门狗只在"备份文件还在"时才动手，备份没了它就认为已经收尾干净、安静退出。
于是代理永久停在一个死端口上：浏览器把所有请求发给一个没人应答的地址，
表现就是哔哩哔哩、百度……**所有网页都打不开**，而用户完全不知道原因。
更糟的是以前 `restore-proxy.js` 遇到"没有备份"会直接说"设置是干净的"然后退出，
把最容易断网的这一种情况漏掉了。

现在：

- `sysproxy.status()` 会检测 `orphan`（开关开 + 指向本程序 + 无备份 + 端口无人监听）；
- `restore-proxy.cmd` 遇到孤儿代理会说明情况并**把代理开关关掉**（无备份时不知道
  服务器地址原本是什么，所以只关开关，绝不删用户的配置）；
- 界面概览页检测到孤儿代理时会显示红色警告条 + 「关闭系统代理（立刻恢复上网）」按钮。

### 修复（系统代理还原相关）

**残留的互斥标记会让"退出时还原"永久失效**（`launcher.js` / `watchdog.js`）

这是本版唯一一处正确性修复，而且是被测试跑出来的真实现象：
一次还原写到一半进程被杀，`proxy-restore.claim` 留在磁盘上；
之后每次启动 `claimRestore()` 都因为"文件已存在"而返回 false，
还原被整段跳过、恢复文件也永远不会被清理。

表现是：程序看起来在正常退出，系统代理却一直卡在**已经没有服务监听**的端口上，
用户直接断网，而且重开程序也救不回来。

现在认领前先判断旧标记是不是僵尸（超过 60 秒，或写下它的进程已经不在了），
是就删掉重新认领；启动接管前也会主动清一次。
没有时间戳的老格式标记按"还活着"处理 —— 宁可多让一次，也不在真有人正在还原时插一脚。

**强杀场景的还原时序不再被误判为失败**（`test-restore.js`）

实测确认存在"`launcher` 刚写完注册表就被杀掉、看门狗随后接手补完清理"的路径：
注册表已还原，而恢复文件要再等几百毫秒才消失。
这是**正确的协作流程**（看门狗本来就是干这个的），但旧测试在检测到还原的同一瞬间
就断言文件已删除，于是偶发误报。现在改为等待"最终会被清理"。

### 变更

- 新增 `admin-hosts.js`：只在写 hosts 时弹一次 UAC（父子进程用临时 JSON 文件通信，
  因为 `Start-Process -Verb RunAs` 只能"启动"，拿不到退出码和 stdout）。
- `elevate.js` 的 `relaunchAsAdmin` 增加可选的 `scriptPath` 参数（缺省仍是
  `launcher.js`），让 `admin-hosts.js` 复用同一套提权实现而不是再抄一份。
- `watchdog.js` 新增 `--file` 参数（缺省仍是 `proxy-backup.json`），
  界面那份备份由 server 单独派一个看门狗盯着。
- `server.js` 新增接口：`/api/sysproxy`、`/api/route/forget`、`/api/hosts/remove`。
- `lib/route.js` 新增 `forget(hostname)`：删记录时同步维护 `ip -> record` 反向索引，
  否则索引会一直攥着已废弃的条目。
- `/api/env` 现在会带上系统代理状态，界面首屏就能显示准确开关位置。

### 验证

- `test-regress.js` 46 项、`test-launcher.js` 45 项、`test-ui.js` 21 项、
  `test-hosts.js` 31 项、`test-restore.js` 12 项、`test-replace.js` 10 项、
  `test-elevate.js` 8 项、`test-e2e.js` 22 项，全部通过。
- 端到端实测：经代理下载 8MB 耗时 944ms，吞吐约 9.6 MB/s，冷启动 TTFB 165ms。
- 修复"僵尸互斥标记"之前，`test-restore.js` 的 [A] 用例稳定失败（12 秒内不还原）；
  清掉残留文件后即通过，随后加了僵尸判定，再次运行仍全绿。

## [3.1.0] — 2026-10-05

交互逻辑与系统代理安全的修复版。功能与 3.0.0 完全一致，改动集中在两处：
**用户能直接感知到的交互反直觉**，以及**一处会静默删掉用户代理配置的隐患**。

### 修复

**选 3 之后，新窗口还要再选一次 3**（`launcher.js`）

这是 3.0.0 之前最反直觉的一个问题。双击 `start.cmd` 时进程参数里只有
`[node, launcher.js]`，提权时转发 `process.argv.slice(2)` 拿到的就是**空数组**。
结果是两件事同时出错：

1. 新进程不知道要设系统代理——`--proxy` 丢了；
2. 新进程零参数 → `shouldShowMenu()` 判定为"双击启动" → **菜单又弹一次**。

用户在旧窗口明明选了「管理员 + 系统代理」，却要在新窗口再选一遍同样的 3。
看起来就像程序没记住自己的选择。

现在改为**显式构造**转发参数（`--port` / `--proxy` / `--no-open`），并加 `--decided`
标记告诉新进程"用户已经选过了"。

> 顺带修掉一个二次踩坑：最初写的是 `[...ARGS.rest, '--decided']`。
> 但 `ARGS.rest` 是**给 server.js** 的参数，里面是 `--system-proxy`（告诉界面
> "代理已指向本程序"），而 launcher 自己判断要不要改系统代理看的是 `--proxy`。
> 两者语义不同，直接转发会导致新进程 `proxy=false`，系统代理仍然不设置。

**还原系统代理时会删掉用户原有的代理配置**（`launcher.js` / `watchdog.js`）

`regGet` 原本用 `null` 同时表达两件不同的事：

- 该项原本就不存在（还原时应该删掉）
- 查询本身失败了（此时**绝不能删**）

一旦 `reg query` 因任何原因失败（安全软件拦截、权限、被杀进程），拿到的也是 `null`，
还原时就会执行 `reg delete`——把用户真实的 `ProxyServer` 和那一长串
`ProxyOverride` 分流规则**全部清空**，且极难察觉。

实测记录：用户机器上 `ProxyServer=127.0.0.1:7877`、`ProxyOverride` 是一长串分流规则，
但备份文件里两项都被记成了 `null`。那份备份一旦执行还原，用户配置就没了。

现在 `regGet` 返回三态 `{ok, value, error}`，并连带修掉三处：

- **读不到就拒绝接管**：三项中任一读取失败，程序直接说明原因并退出，
  提示用户可以选 `[1]` 正常启动后手动填代理地址。宁可不接管，也不能无法还原。
- **读不到就绝不删除**：备份里标记 `unknown` 的项，还原时只关代理开关，
  原样保留用户的服务器地址和绕过列表。
- **老备份保守处理**：没有 `unknown` 字段的旧备份按"读不到"处理，不冒险删除。

**恢复文件被覆盖，毁掉唯一能救人的那份备份**

`writeRecovery` 原本无条件覆盖。上一次会话被强杀时备份还留在磁盘上，
这次启动直接覆盖它——于是既丢了上次的真实配置，也没有新配置。
现在用 `'wx'` 独占创建：文件已存在就**拒绝接管**，并提示用户先双击
`restore-proxy.cmd` 再重新启动。

**绕过列表里的特殊字符会被 cmd 吃掉**（`launcher.js`）

`regSet` 原来把命令拼成字符串交给 `exec`，实际经过 `cmd.exe` 解析。
`ProxyOverride` 的值含 `*`、`;`、`<local>`，会被 shell 吞掉一部分，
还原出来的绕过列表悄悄缺项——而用户完全看不出来。
现在改用 `execFile` + 参数数组，不经过 shell。

**菜单里"系统代理已开启"会误报**（`launcher.js`）

原先只看 `ProxyServer` 是否包含本程序端口，不看 `ProxyEnable`。
代理开关是关的（用户根本没在用代理）时也会显示"已开启"。
现在两项都要满足才算开启。

### 变更

- **提权成功后的引导更明确**：明确告诉用户"新的窗口已经接管了系统代理，
  不用再选一次了"，并停在"按任意键关闭这个窗口"（原先只有 400ms 停留，
  用户来不及看清就以为闪退）。
- **提权失败不再硬等 3 秒**：改为可交互——回车以普通权限继续、`q` 退出。
  硬等期间用户来不及反应，等于剥夺了选择权。
- 菜单在**已是管理员**时把 3/4 降级为普通选项，不再白跑一次 `isElevated()` 判断
  并打印一句多余的"已以管理员身份运行"。
- **新增 `test-launcher.js`**（46 项断言）：覆盖「菜单选择 → 参数生效 →
  提权转发内容正确 → 新进程不重弹菜单」这条**完整链路**。
  在此之前，启动器几乎没有测试——菜单只是"grep 到有 `[1] [2]` 就当通过"，
  提权也只测了 `relaunchAsAdmin` 函数本身。这正是最反直觉的那个 bug
  一路漏到用户手上的原因：单测都通过，只有真跑才暴露。
- 新增退出码 `5`（读不到原代理设置，已放弃接管）与 `6`（有未清理的恢复文件，
  已放弃接管），两者都会给出明确的处理建议而不是默默退出。
- 注册表路径抽成 `PROXY_KEY` 常量，`launcher.js` 与 `watchdog.js` 不再各写一份。

### 验证

- `test-launcher.js` 46 项、`test-regress.js` 46 项、`test-ui.js` 21 项、
  `test-hosts.js` 31 项，全部通过。
- **端到端确认「不用再选一次」**：以 `--decided` 启动并强制打开菜单
  （`ACCEL_FORCE_MENU=1`），输出中不含"请选择"，同时日志确认
  `proxy=true` 且 `--system-proxy` 已转发给 server.js。
- **回归有效性反向验证**：临时注入 4 处破坏（去掉删除保护、去掉幂等守卫、
  部分还原不清恢复文件、备份改回非独占创建），测试准确报出 5 项失败，
  其中「命令数从 3 涨到 6」直接证明幂等守卫失效。恢复后重新全绿。
- 「只关开关不删配置」这条用注入的注册表记录器断言：还原过程中
  **一条 `reg delete` 都没执行**，只有 1 次 `ProxyEnable` 写入。

### 已知限制（与 3.0.0 相同，未改变）

- 吞吐读数是偏低的下界，不是精确带宽；**排序结论可靠**，但别当带宽测试工具用。
- 只对延迟最优的前 6 个候选测吞吐（每协议族最多 3 个），其余按延迟排名。
- 代理模式只影响遵守系统代理设置的程序；游戏平台必须用 hosts 模式。
- 代理转发阶段默认不校验证书以兼容自签证书的更新器。

## [3.0.0] — 2026-10-04

第二代目录（V3）。**功能与配置方式完全向后兼容**，V2（内部版本 1.0.0 / 1.1.0）的用法
——双击 `start.cmd`、`--port` / `--policy` / `--socks5` 等参数、浏览器与 IDM 代理配置
——均不受影响。除修复正确性缺陷外，本版另新增回归测试与本更新日志。

这一轮修掉的问题都属于同一类：**表面能跑、实际结果是错的**，而且多数不会报错，
只会让界面上的数字悄悄失真。因此本版的重点是修复正确性，并补上能拦住回归的测试。

### 修复

**流量统计凭空翻倍**（`lib/proxy.js`）

- `_pipe` 的 `teardown` 绑定在 `client`/`upstream` × `error`/`close` 共 4 个事件上。
  正常关闭时 `'close'` 会在两侧各触发一次，于是一次下载被统计成两份。
  实测 64KB 报文被统计成 **131072 字节**，界面上的流量数字直接虚高一倍。
  现在 `teardown` 带幂等守卫。
- `stats.requests` 在 `_onRequest` 与 `_relayHttp` 中各累加了一次，
  所有 HTTP 转发请求都被记成 2 条。
- `_relayHttp` 的响应字节在 `'end'` 与 `'error'` 两个分支都会累加，同样存在重复，
  已加幂等保护。
- `Stats.byIp` 记录"历史上用过的每个 IP"，只增不减，且 `snapshot()` 每次全量遍历。
  现按最后使用时间淘汰（上限 500）。

**后台精化在拿假数据改写路由**（`lib/route.js`）

`_refine` 有两个问题，都会直接影响优选结论：

1. 它对**所有**存活的候选 IP 测吞吐，没有上限。一个解析出二三十个 A/AAAA 记录的
   目标会同时发起三十个测速，每个都可能等满超时——代理进程因此长期挂着几十个
   socket，界面上的「活跃连接」直接飙红。
2. 它直接拿 `https://域名/` 去测，**跳过了目标标定**。根路径往往只返回几十 KB 的
   目录列表页，会算出一个漂亮但假的吞吐，再拿这个假数据改写排序——比不测更糟。

现在改为限量 + 先标定。标定失败时会记一笔（`speedDone`），
不会在每次 TTL 过期时重跑注定失败的标定。未被实测的候选保留原有延迟数据，不会被丢弃。

**路由表热路径是全表扫描**（`lib/route.js`）

`reportSuccess` / `reportFailure` 每次连接都要遍历全部 `records`（上限 2000），
而这是**每建一个连接**就执行一次的路径。下载页几十个并发连接意味着每秒几千次
无效遍历。现改为 `ip -> Set<record>` 反向索引，实测命中单个 IP 只涉及 2 条记录
而非 500 条。索引随记录淘汰同步清理，不会攥住已废弃的 record。

**DNS 解析做了无用查询**（`lib/probe.js`）

- `query()` 中 A 查询失败后仍会执行一次 `resolve6`，AAAA 失败后也会执行 `resolve4`
  ——结果被丢弃，但那次网络往返真实发生。
- `opts.dnsServers` 被原样记录进返回值，却**从未参与实际查询**：传了它，查询照样走
  系统 DNS。现在 `setServers()` 真正生效。

**静态文件的路径前缀判断有洞**（`server.js`）

`full.startsWith(PUBLIC)` 在同级存在 `public-secret` 这类目录时会把越界路径误判为
合法。现改为带路径分隔符比较。

**定时器泄漏与请求体挂死**（`server.js`）

- `raceText` 的超时定时器从不清理（原写法是声明后 `void t`），刷新界面会持续堆积
  悬空定时器，把事件循环撑到超时才结束。
- `readJson` 超限时只 `req.destroy()` 而不 resolve，调用方 `await` 永久挂死；
  且用字符串累加大 body，内存复制是 O(n²)。现引入 `MAX_BODY`（256KB）与
  `readBody()`，超限返回 413 并给出明确信号。

### 变更

- **新增 `test-regress.js`**（46 项断言）：每条断言都对应一个已修复的真实缺陷，
  不是为了覆盖率而测。已接入 `npm test` 并排在最前——它最快，也最能挡住回归。
- 版本号改为从 `package.json` 单一来源读取。此前 `server.js` 硬编码了一份、
  `package.json` 又一份，改的时候容易只改一处，导致 `/api/health` 报出与实际不符
  的版本。
- `route.js` 的 `minProbeInterval` 定义后从未被读取，已移除；
  `entryMaxAge` 此前同样未被使用，现在真正参与记录淘汰。

### 验证

- `test-regress.js` 46 项、`test-ui.js` 21 项、`test-hosts.js` 31 项、
  `test-e2e.js` 22 项，全部通过。
- 实测经代理下载 8MB 耗时 928ms，吞吐约 9.8 MB/s（已扣除 TTFB）。
- 回归测试的有效性经过反向验证：临时移除幂等守卫后，测试准确报出
  `131072，应为 65536`，与缺陷症状一致。

### 开发过程中的一次事故记录

修 `readJson` 时用脚本批量把 9 个 handler 的 `readJson(req)` 替换为
`readBody(req, res)`，**连 `readBody` 函数体内部那一行也一起替换了**，
当场变成无限递归，服务崩溃在 `RangeError: Maximum call stack size exceeded`。

批量改代码后必须跑测试，不能相信自己写的替换规则。
`test-regress.js` 中已有一条断言专门守住这个位置。

### 已知限制（与 1.0.0 相同，未改变）

- 吞吐读数是偏低的下界，不是精确带宽；**排序结论可靠**，但别当带宽测试工具用。
- 只对延迟最优的前 6 个候选测吞吐（每协议族最多 3 个），其余按延迟排名。
- 代理模式只影响遵守系统代理设置的程序；游戏平台必须用 hosts 模式。
- 代理转发阶段默认不校验证书以兼容自签证书的更新器。

## [1.0.0] — 2026-10-02

首个正式版本。

### 功能

- 多候选 IP 竞速：把优选出的 N 个 IP 错峰发起，谁先握手成功用谁
  （Happy Eyeballs 加强版），单个 IP 临时抽风只多花几十毫秒。
- 实测吞吐优选：首字节到达后才开始计时，两段式自适应采样，
  窗口过短则放大样本重测。
- 目标标定：只给域名时先标定出可下载的大文件，标定不出来就退回按延迟排序，
  **绝不编造数字**。
- 两阶段路由：首包只做 TCP 延迟探测立即放行，真实吞吐测速放后台做、完成后就地
  更新排序。冷启动首字节 33ms。
- 两种加速机制：本地代理（浏览器 / IDM / aria2 / curl，无需管理员）
  与 hosts 重定向（Steam / Epic /战网等，需要管理员）。
- 14 个内置平台，支持多模式共存与按模式还原，用户原有 hosts 内容零破坏。
- 可选 SOCKS5 端口。
- 中文启动菜单、双击 `start.cmd` 即可。
- 看门狗兜底：主进程被强杀 / 崩溃时自动还原系统代理。
- `restore-proxy.cmd` 救援入口。

- 流量统计重复累加，显示值虚高一倍。
- 后台精化不限量且不做目标标定，可能用假吞吐改写路由。
- 路由表连接结果上报为全表扫描。
- DNS 解析产生无用查询，`dnsServers` 参数不生效。
